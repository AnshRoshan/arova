# Arova Midnight UI tokens

DESIGN.md at the repo root is the visual authority — read it before touching styling, and do not fork its values into this file. This page records only what a non-visual agent needs. **As of 2026-10-06 the authority file describes the Midnight Edition** (D-18): the built world had moved to a rewritten `:root` plus a light layer while the docs still described the retired Graphite palette; both are now synced to the code, and `identity.test.ts` parses `globals.css` for the values it measures, so the three cannot drift apart silently.

- One `:root` in `src/app/globals.css` is normative. Elevation comes from surface steps and hairlines, with the light layer adding depth on top: `--void #07080d` (icon rail + page ground) → `--panel #0c0e15` → `--sheet #0f111a` (working ground) → `--card #151824` → `--raised #1e2232` (hover/selected) → `--sunken #0a0c13` (inputs, code well). The ramp is tight by design; hairlines and the light layer separate what luminance does not.
- Text: `--ink #eef0f8` / `--ink-2 #a8aec6` / `--ink-3 #8b92ad`. `--ink-3` is tuned to clear 4.5:1 on `--raised`, the lightest surface tertiary text lands on; do not darken it. The test measures this against the live stylesheet.
- One interactive accent family: `--azure #8b9bff`, `--azure-bright #b4beff` on hover/focus, `--azure-wash #1b2147` / `--azure-line #323c82` for its tint family, `--on-azure #0a0d28` as the dark glyph on every light fill. The accent's **fill expression** is `--grad` (indigo `#7e8fff` → violet `#a187ff` → `#c78bff` at 135°) with `--grad-soft` as its 10–16% wash; a gradient fill always takes the dark glyph.
- **Channels, not literals:** `--azure-rgb` / `--indigo-rgb` / `--violet-rgb` / `--ran-rgb` / `--waiting-rgb` / `--fault-rgb` are space-separated RGB triplets (`139 155 255` …). Every glow, hairline, focus ring and aurora mixes from these — `rgb(var(--azure-rgb) / .12)`, `color-mix(in srgb, var(--sec) 18%, …)`. Never write a hardcoded `rgba()` of these families; the 2026-10-06 pass retired 40+ of them into these tokens.
- Light-layer tokens and their one jurisdiction: `--grad`/`--grad-soft` = press/selected fills; `--glow` = the rail logo tile only; `--edge` = the inset bevel on raised cards (`.rows`, `.block`, `.pulse-strip`, `.agent-card`, `.reasoning`, `.prov`, `.memory-panel`, `.dialog`, control-room cards); `--lift` = their soft downward shadow (still not `--shadow-lift`); `--dur .22s` = the layer's shared transition; the aurora = three radials behind `.workbench`, the primary tinted with the open room's `--sec`.
- Room colour: each of the six sections owns one hue as `--sec` (`SECTION_COLORS` in `src/lib/identity.ts`) and paints the room's chrome — active rail mark + wash, panel title/item icons/tabs/hairline, pane headings, sheet-bar hairline — **and, since 2026-10-06, the primary stage aurora**. It marks *where you are*; buttons, links and focus stay azure in every room. See the Room-Colour Rule in DESIGN.md.
- `--ran #5fce9b`, `--waiting #e8b25c`, `--fault #f48cab` (each with `-wash`/`-line` **and** an `-rgb` channel) are **state semantics**, not palette. Use them only where a stored row produced that state — including the faint state-dot glow, which inherits the Stored-Row Rule exactly.
- Identity tints live in `src/lib/identity.ts`: **three** (sage `#a8d98a`, aqua `#70d2db`, mauve `#c4a3dd`), reaching CSS as `--h-ink/-tile/-glyph/-wash/-line`. They mark *which agent*, never status. The count is a measured ceiling, not taste: with the accent at ~232° and state at 152°/37°/342°, the cool half of the wheel holds three marks at 30° separation and no more. `identity.test.ts` asserts contrast and separation **against the live `globals.css`** (it parses the stylesheet for the surface/accent/state hexes), so adding a fourth hue — or swapping the palette without re-checking — fails until decided deliberately. The avatar glyph leads; the tint is secondary.
- Radii: tokens `--r-sm 8px` / `--r 12px` / `--r-lg 16px` plus `99px` pills, with a documented one-off ladder for the chrome between them (9 tab buttons · 10 buttons/inputs · 11 list rows/nodes · 13 rail · 14 row groups/cards · 18 composer/control-room cards · 20 dialog/hero · 24 welcome). A radius on that ladder is not drift. `--code-bg #080a10` is the only recessed dark surface besides the rail; do not reuse it for cards.
- Fonts are **self-hosted** through `next/font/local` in `src/app/layout.tsx` from `src/app/fonts/*.woff2` (variable, latin) as `--font-body` (DM Sans) / `--font-display` (Manrope) / `--font-mono` (JetBrains Mono). There is no CDN `@import` and no build-time Google fetch — this host's TLS kills it, which broke `npm run build`. Adding a face means dropping the woff2 in `src/app/fonts/` and wiring it there. Mono is for measurement only.
- Shadows: `--lift` (resting raised cards), `--edge` (their inset bevel), `--glow` (rail logo), and `--shadow-lift` — **only** on floating layers (dialog, toast, jump pill, overlay panel/board). A resting card never takes `--shadow-lift`.
- Layout: 68px icon rail · 276px section panel · fluid work surface · 320px activity board. Breakpoints 1250 (board → overlay) and 860 (rail → 60px, panel → full-width step, gutter tightens). `.only-narrow` / `.only-wide` / `.only-mobile` are the only visibility helpers.
- A small set of single-use hexes (hover steps, text steps, selection, scrollbar, gradient-text ends) is deliberate and enumerated in DESIGN.md. If one is needed a second time, promote it to `:root` rather than repeating the literal. Cleanup owed: the base layer still declares ~10 hover/selection/scroll steps the light layer overrides — delete each only after a capture proves it dead.
- All summary values come from the board API; seeded sample rows never count as completed work. The retired worlds are gone — no warm ivory/lilac "Studio Edition", no cool-paper "Bench Notebook", no taped slips, no printed state legend, no hero illustration. Do not reintroduce any of them.
